# 01. Перший запит: список користувачів

Рівень: ★☆☆ · Ціль: 10 хв (ідеал 7)

База бази: один `GET`, три стани, cleanup. Після цієї задачі код завантаження має писатися
без роздумів. Наживо на це легко піти 30 хвилин, і дані так і не з'являться.

## Завдання

У `Task.tsx` захардкожено трьох користувачів. Заміни їх на дані з `GET /api/users`.

```json
[{ "id": "u_1", "name": "Олена Коваленко", "email": "olena@example.com", "city": "Київ" }]
```

Тип `User` уже є в `src/api/types.ts`. **Спершу відкрий цей файл.**

## Вимоги

1. Loading: поки йде запит, показати «Завантаження…» (або skeleton).
2. Error: якщо `!res.ok`, показати текст з тіла `{ "error": "..." }`.
3. Empty: якщо масив порожній, показати «Користувачів немає».
4. Список з `key={user.id}`.
5. `AbortController` + `return () => controller.abort()` у `useEffect`.
6. Стан одним union-типом: `loading | error | success`.

## Як перевірити

- Звичайний запуск: список з 7 людей.
- Заміни URL на `/api/users?fail=1`: має бути текст помилки «Сервер тимчасово недоступний».
- `/api/users?empty=1`: порожній стан.
- `/api/users?delay=3000` і одразу клікни на іншу задачу: у Network запит має стати `canceled`.
- У Network видно два запити, перший `canceled`: це StrictMode, і abort працює.

## Порядок роботи (тренуй саме його)

1. 1 хв: прочитати типи, подивитись верстку, сказати план вголос.
2. 3 хв: `getJson<T>` і `useEffect` з `console.log(data)`. Перевірити в браузері!
3. 3 хв: стан-union і рендер списку.
4. 2 хв: loading, error, empty. Перевірити через `?fail=1` і `?empty=1`.

## На що дивиться інтерв'юер

- Перевірка `res.ok` (fetch не кидає помилку на 4xx/5xx).
- Cleanup в ефекті, а не просто створений `AbortController`.
- `setState` не викликається після abort.
- `key` з id, а не індекс.
