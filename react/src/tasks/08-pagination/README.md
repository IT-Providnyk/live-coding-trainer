# 08. Пагінація «Показати ще»

Рівень: ★★★ · Ціль: 20 хв

Бонус-пункт, який часто дають у задачах зі списком переказів, якщо база готова раніше.

## API

```
GET /api/transfers?page=2&limit=5
→ { "items": [...], "total": 24, "page": 2, "limit": 5, "totalPages": 5 }
```

## Завдання

1. При відкритті завантажити першу сторінку (`limit=5`).
2. «Показати ще» довантажує наступну сторінку і **додає** рядки до вже показаних.
3. Поки сторінка вантажиться, кнопка неактивна з текстом «Завантаження…». Подвійний клік
   не шле два запити і не пропускає сторінку (перевір: 5 → 10 рядків, а не 5 → 15).
4. На останній сторінці кнопка зникає.
5. Під таблицею «Показано 10 з 24».
6. Помилка на сторінці N: уже завантажені рядки лишаються, під ними помилка і «Спробувати ще раз»,
   яка повторює саме сторінку N. Перевір з `&fail=0.3` у URL.
7. У StrictMode рядки не дублюються. Перевір, що на старті рівно 5 рядків, а не 10.

## Пастки

- StrictMode запускає ефект двічі. Якщо в ефекті `setItems(prev => [...prev, ...new])` без
  abort, перша сторінка додасться двічі.
- Стан «вантажимо першу сторінку» і «вантажимо наступну» виглядають по-різному: перший це
  повноекранний loading, наступні це кнопка.
- `key={t.id}`: при дублікатах React покаже warning у консолі, подивись туди.

## Follow-up

- «Як не запитувати контакти повторно для вже відомих id?» (кеш Map, запитувати тільки нові)
- «Нескінченний скрол замість кнопки?» (IntersectionObserver на останньому рядку)
- «10 000 рядків?» (віртуалізація)
