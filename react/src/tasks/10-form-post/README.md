# 10. Форма нового переказу: контрольовані поля, валідація, POST

Рівень: ★★★ · Ціль: 25 хв

Друга найчастіша live coding задача після «підключи API»: форма з валідацією і відправкою.

## API

```
GET /api/contacts → { items: Contact[] }

POST /api/transfers
Content-Type: application/json
{ "counterpartyId": "c_101", "amount": 125050, "currency": "UAH", "description": "Оренда" }

201 → створений Transfer (status: "pending")
400 → { "error": "..." }  невалідне тіло
422 → { "error": "Limit exceeded: max 100 000,00 per transfer" }
```

## Завдання

1. Отримувач: `<select>` з контактів `GET /api/contacts`. Поки вантажаться, select disabled.
2. Сума: текстове поле, користувач пише як звик: `1250`, `1250,5`, `1 250,50`, `1250.50`.
   Перетвори в **цілі копійки** без помилок float: `"0,29"` має дати `29`, а не `28.999...`.
3. Валюта: UAH / USD / EUR / PLN.
4. Опис: обов'язковий, до 100 символів.
5. Валідація при сабміті: помилка під кожним невалідним полем, запиту немає.
   Після першої спроби помилки оновлюються під час набору.
6. Відправка: кнопка disabled і «Надсилаю…», повторний сабміт неможливий.
7. Помилка сервера (спробуй суму `200000`): текст з `{ error }` над кнопкою, введене не стирається.
8. Успіх: «Переказ tr_025 створено, статус pending», форма очищається.

## Вимоги

- Контрольовані інпути (`value` + `onChange`), один об'єкт стану форми або кілька useState, як зручно.
- `onSubmit` на `<form>` з `e.preventDefault()`, а не onClick на кнопці (Enter теж має працювати).
- Валідація чистою функцією `validate(values) → errors`.
- Парсинг суми чистою функцією `parseAmount(input) → number | null`.

## Перевірка

- `0,29` → у Network Payload `"amount": 29`.
- `abc`, `0`, `-5`, `1,234` → помилка «Введи суму, наприклад 1250,50».
- `200000` → 422 з текстом ліміту.
- Подвійний клік по кнопці (і Enter двічі) → один запит у Network. Підказка: guard через стан тут не допоможе, подумай чому.
