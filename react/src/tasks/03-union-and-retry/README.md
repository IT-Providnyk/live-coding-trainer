# 03. Три useState → union, кнопка «Спробувати ще раз»

Рівень: ★★☆ · Ціль: 12 хв

## Завдання

`Task.tsx` уже завантажує користувачів, але на трьох окремих `useState` (`isLoading`, `error`,
`users`). Запит іде на `/api/users?fail=0.5`, тобто падає приблизно кожен другий раз.

1. Натисни «Перемонтувати» кілька разів і знайди баги: які неможливі комбінації станів
   з'являються на екрані?
2. Перепиши стан на один union `loading | error | success`.
3. Додай кнопку «Спробувати ще раз» у блоці помилки. Кнопка перезапускає ТОЙ САМИЙ ефект,
   а не дублює код запиту.
4. Під час повторного запиту кнопка показує «Завантаження…» і неактивна.

## Вимоги

- Жодного дубльованого коду fetch (не копіюй тіло ефекту в onClick).
- Abort і cleanup лишаються.
- Після успішного повтору помилка зникає, після невдалого старі дані не висять.

## Підказка

Найпростіший спосіб перезапустити ефект: лічильник у стані, який входить у deps.
`const [reloadKey, setReloadKey] = useState(0)` → `useEffect(..., [reloadKey])`.

## На що дивиться інтерв'юер

- Чи розумієш, чому три булеві стани гірші: `isLoading && error` одночасно, `error` не
  скинувся після успіху.
- Retry через deps ефекту, а не копіпаст.
- `setState` у функціональній формі для лічильника: `setReloadKey((k) => k + 1)`.
