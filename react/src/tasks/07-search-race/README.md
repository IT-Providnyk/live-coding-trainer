# 07. Пошук: debounce і race condition

Рівень: ★★★ · Ціль: 20 хв

## Завдання

`Task.tsx` шукає товари через `GET /api/products?q=...` на кожне натискання клавіші.
Сервер відповідає з випадковою затримкою 200–1200 мс.

1. Швидко надрукуй «ноутбук», потім зітри й надрукуй «мишка». Подивись, що показує список
   і що у вкладці Network. Опиши баги словами, перш ніж правити.
2. Виправ:
   - **debounce 300 мс**: запит іде, коли користувач перестав друкувати;
   - **race condition**: на екрані завжди результати для ПОТОЧНОГО рядка, навіть якщо стара
     відповідь прийшла пізніше за нову;
   - попередній запит скасовується (`AbortController`), у Network видно `canceled`;
   - порожній рядок: запиту немає, підказка «Почни вводити назву товару»;
   - стани: «Шукаю…», «Нічого не знайдено за "<q>"», помилка, список з ціною.

## Вимоги

- Інпут лишається швидким: текст у полі оновлюється одразу, затримується тільки запит.
- Пробіли по краях не змінюють запит (`trim`).
- Без бібліотек.

## Підказки

- Два шматки стану: `query` (що в полі) і `debouncedQuery` (що шукаємо).
- Debounce значення: `useEffect` з `setTimeout` і `clearTimeout` у cleanup.
- Race: cleanup ефекту з `controller.abort()` закриває його одразу.
- `encodeURIComponent(q)` або `URLSearchParams`.
