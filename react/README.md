# React-тренажер: завантаження даних, стани, форми

10 задач на React + TypeScript з вбудованим мок-API. Кожна задача: умова (`README.md`),
заготовка (`Task.tsx`) і еталон із розбором (`Solution.tsx`). Задачі зібрані навколо того,
що найчастіше ламається на live coding: дані на екрані якомога раніше, правильні типи
відповіді API, union-стан, cleanup, паралельні й залежні запити, похідні дані.

## Запуск

Потрібен Node.js 22+.

```bash
cd react
npm install       # один раз
npm run dev       # http://localhost:5180
```

Окремого сервера немає: API працює всередині Vite (`mock-api/plugin.js`), тому
`fetch('/api/...')` просто працює. Лог запитів видно в терміналі.

У застосунку зліва список задач, зверху три вкладки:
- **Умова**: README задачі;
- **Моє рішення**: твій `src/tasks/NN-*/Task.tsx`;
- **Еталон**: `Solution.tsx`.

«Перемонтувати» запускає компонент з нуля (зручно для перевірки loading і StrictMode).

Перевірка типів: `npm run typecheck`.

## Мок-API

| Ендпоінт | Затримка | Що повертає |
|---|---|---|
| `GET /api/users` | ~600 мс | `User[]`. `?empty=1` дає `[]` |
| `GET /api/transfers` | ~700 мс | `{ items, total }`; з `?page&limit` ще `page, limit, totalPages` |
| `GET /api/rates` | ~1500 мс | `{ base, rates, updatedAt }` |
| `GET /api/contacts` | ~500 мс | `{ items: Contact[] }` |
| `POST /api/contacts/batch` | ~600 мс | `{ items }` за `{ ids }`, максимум 50, потрібен `Content-Type` |
| `GET /api/products?q=` | 200–1200 мс випадково | `{ q, items }` |
| `POST /api/transfers` | ~800 мс | 201 зі створеним переказом; 400 або 422 з `{ error }` |

На будь-якому ендпоінті:
- `?fail=1`: завжди 500 `{ error }`; `?fail=0.5`: падає з імовірністю 50%;
- `?delay=3000`: своя затримка;
- `DELAY=0 npm run dev`: без затримок узагалі.

Типи відповідей: `src/api/types.ts`. **Першим ділом на будь-якій співбесіді відкривай файл типів.**

Створені через форму перекази живуть у пам'яті до перезапуску `npm run dev`.

## Як працювати

1. Відкрий «Умову». Перші 1–2 хвилини тільки читаєш: типи, верстка, що означає кожне число.
2. Скажи план вголос (так, навіть наодинці). Засічи час.
3. Пиши в `Task.tsx`, перевіряй у браузері **після кожного кроку**, а не в кінці.
4. Застряг на 10 хвилин: подивись еталон, закрий, напиши з нуля.
5. Після рішення прочитай «Розбір» унизу `Solution.tsx`: там пастки й follow-up питання.
6. Повтори задачу через 2–3 дні: `git checkout src/tasks/NN-*/Task.tsx` поверне заготовку.

## Для інтерв'юера / ментора

Будь-яку задачу можна дати як пробну співбесіду: кандидат бачить «Умову» і `Task.tsx`,
інтерв'юер тримає `Solution.tsx`. Розбір містить follow-up питання. Задача 02 добре працює як «code review
наживо»: кандидат читає код уголос і пояснює, що не так.
